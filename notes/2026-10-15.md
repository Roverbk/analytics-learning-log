## P3 (BigQuery) - final
-- Input grain: one row = one transaction
-- Output grain: one row = one card (card_id)
-- Window needed? yes, because "consecutive" means comparing each date to its neighbours in date order; GROUP BY can't see order
-- Keep a card when: it has at least one island of 3+ distinct days
WITH dedupe AS (
  SELECT DISTINCT card_id, txn_date FROM transactions
),
ranked AS (
  SELECT card_id, txn_date,
         ROW_NUMBER() OVER (PARTITION BY card_id ORDER BY txn_date) AS rn
  FROM dedupe
),
labeled AS (
  SELECT card_id, DATE_SUB(txn_date, INTERVAL rn DAY) AS island
  FROM ranked
),
island_sizes AS (
  SELECT card_id, COUNT(*) AS days_in_island
  FROM labeled
  GROUP BY card_id, island
)
SELECT DISTINCT card_id FROM island_sizes WHERE days_in_island >= 3;

## DL User Shopping Sprees (Postgres) - accepted
-- Input grain: one row = one transaction
-- Output grain: one row = one user (user_id)
-- Window needed? yes, because consecutive dates need date order; GROUP BY can't see order
-- Keep a user when: they have at least 3 consecutive days with transactions
WITH dedupe AS (
  SELECT DISTINCT user_id, transaction_date::date AS txn_day
  FROM transactions
),
ranked AS (
  SELECT user_id, txn_day,
         ROW_NUMBER() OVER (PARTITION BY user_id ORDER BY txn_day) AS rn
  FROM dedupe
),
labeled AS (
  SELECT user_id, txn_day - rn::int AS island
  FROM ranked
),
island_sizes AS (
  SELECT user_id, COUNT(*) AS days_in_island
  FROM labeled
  GROUP BY user_id, island
)
SELECT DISTINCT user_id FROM island_sizes
WHERE days_in_island >= 3
ORDER BY user_id;

## DL Repeated Payments (Postgres) - cleaned (HINTED)
-- Input grain: one row = one transaction
-- Output grain: one row total, one column: payment_count
-- Window needed? yes, because I need the previous identical payment's timestamp on the same row
-- Keep a row when: same merchant, card, amount repeats within 10 min of the previous one
WITH prev AS (
  SELECT transaction_timestamp,
         LAG(transaction_timestamp) OVER (
           PARTITION BY merchant_id, credit_card_id, amount
           ORDER BY transaction_timestamp, transaction_id
         ) AS prev_ts
  FROM transactions
),
gaps AS (
  SELECT transaction_timestamp - prev_ts AS diff FROM prev
)
SELECT COUNT(*) AS payment_count
FROM gaps
WHERE diff <= INTERVAL '10 minutes';

## Concepts
- The tool I didn't know to use was LAG, and it's for putting the previous
  row's VALUE on the current row so I can compare (time gap, amount change).
  ROW_NUMBER gives POSITION, not values: rn = 2 says nothing about minutes.
- Why date - rn is constant in a streak: date and rn both go up by 1 each
  row, so the difference doesn't change. A gap in dates breaks it.
- Cast = convert type. timestamp::date drops the time, so same-day rows
  dedupe. Portable: CAST(x AS DATE). BigQuery also: DATE(ts).
- Primary key as last tie-breaker = reproducible result.

## Dialect notes
- Postgres: ROW_NUMBER returns bigint; date - bigint fails. Use rn::int.
  MySQL/BQ: DATE_SUB(d, INTERVAL rn DAY), no issue.
- Postgres: d - n * INTERVAL '1 day' returns a timestamp (works, less clean).
- Timestamp gap <= 10 min:
  Postgres: ts - prev_ts <= INTERVAL '10 minutes' (interval vs interval)
  MySQL:    TIMESTAMPDIFF(MINUTE, prev_ts, ts) <= 10
  BigQuery: TIMESTAMP_DIFF(ts, prev_ts, MINUTE) <= 10
