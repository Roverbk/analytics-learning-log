## DL Repeated Payments (Postgres)
```sql
-- Input grain: one row = one transaction
-- Output grain: one row total; column = payment_count
-- Window needed? yes, because LAG puts the previous same card/merchant/amount timestamp on each row
-- Keep a row when: the same card, merchant and amount was charged <= 10 min before it
WITH prev AS (
  SELECT merchant_id, credit_card_id, amount, transaction_timestamp,
         LAG(transaction_timestamp) OVER (
           PARTITION BY merchant_id, credit_card_id, amount
           ORDER BY transaction_timestamp, transaction_id
         ) AS prev_ts
  FROM transactions
)
SELECT COUNT(*) AS payment_count
FROM prev
WHERE transaction_timestamp - prev_ts <= INTERVAL '10 minutes';
```
- Improved vs Oct 15: LAG first (not ROW_NUMBER), one COUNT (not GROUP BY + SUM), current − previous.
- Tie-breaker forgot on first send (5th time), added on second.
- Timestamp − timestamp = interval in Postgres → compare to `INTERVAL '10 minutes'`.
  MySQL: `TIMESTAMPDIFF(MINUTE, prev_ts, ts) <= 10`. BQ: `TIMESTAMP_DIFF(ts, prev_ts, MINUTE) <= 10`.

## #180 Consecutive Numbers: window version (MySQL)
```sql
-- Input grain: one row = one log entry (id, num)
-- Output grain: one row = one distinct num that appears 3+ times in a row
-- Window needed? yes, because LAG puts the previous 2 nums on each row so I can compare neighbours
-- Keep a row when: num equals both previous nums
WITH prev AS (
  SELECT id, num,
         LAG(num, 1) OVER (ORDER BY id) AS prev_num_1,
         LAG(num, 2) OVER (ORDER BY id) AS prev_num_2
  FROM Logs
)
SELECT DISTINCT num AS ConsecutiveNums
FROM prev
WHERE prev_num_1 = num AND prev_num_2 = num;
```
- First draft returned COUNT (misread the output). Fixed.
- DISTINCT needed: run of 4, or two separate runs, prints the num more than once.
- First 2 rows get NULL from LAG; `NULL = num` is never true → they drop out without IFNULL.
- `id` is the PK → no tie-breaker needed.
- Done in 18 min, no hints.

## DL Card Launch Success
```sql
-- Input grain: one row = one card_name per issue_month/issue_year
-- Output grain: one row = one card_name (its launch month)
-- Window needed? yes, because I pick one row per card (earliest month)
-- Keep a row when: it is the card's earliest year-month (rn = 1)
WITH ranked_cards AS (
  SELECT card_name, issued_amount, issue_month, issue_year,
         ROW_NUMBER() OVER (
           PARTITION BY card_name
           ORDER BY issue_year, issue_month, issued_amount DESC
         ) AS rn
  FROM monthly_cards_issued
)
SELECT card_name, issued_amount
FROM ranked_cards
WHERE rn = 1
ORDER BY issued_amount DESC;
```
- Syntax bug: `;` inside the CTE ends the whole statement.
- Pattern: pick a row from a group → ROW_NUMBER + WHERE rn = 1.
- Added tie-breaker unprompted (`issued_amount DESC`).
- Year/month as integers sort fine; as strings '10' < '2'. Real date:
  Postgres `MAKE_DATE(y, m, 1)`, BQ `DATE(y, m, 1)`.

## #1321 Restaurant Growth (MySQL), LAG version
```sql
-- Input grain: one row = one customer visit (customer, day, amount)
-- Output grain: one row = one day that has a full 7-day window
-- Window needed? yes, because LAG puts the previous 6 days' totals on each row
-- Keep a row when: all 6 previous days exist (sum is not NULL)
WITH day_totals AS (
  SELECT visited_on, SUM(amount) AS amount
  FROM Customer
  GROUP BY visited_on
),
prev_days AS (
  SELECT visited_on, amount,
         LAG(amount, 1) OVER (ORDER BY visited_on) AS prev_1,
         LAG(amount, 2) OVER (ORDER BY visited_on) AS prev_2,
         LAG(amount, 3) OVER (ORDER BY visited_on) AS prev_3,
         LAG(amount, 4) OVER (ORDER BY visited_on) AS prev_4,
         LAG(amount, 5) OVER (ORDER BY visited_on) AS prev_5,
         LAG(amount, 6) OVER (ORDER BY visited_on) AS prev_6
  FROM day_totals
),
seven_day_sums AS (
  SELECT visited_on,
         amount + prev_1 + prev_2 + prev_3 + prev_4 + prev_5 + prev_6 AS seven_day_sum
  FROM prev_days
)
SELECT visited_on,
       seven_day_sum AS amount,
       ROUND(seven_day_sum / 7, 2) AS average_amount
FROM seven_day_sums
WHERE seven_day_sum IS NOT NULL
ORDER BY visited_on;
```
- Key step: GROUP BY day FIRST. Several customers per day → "6 rows back" ≠ "6 days back".
- NULL trick: first 6 days have a NULL LAG → NULL + anything = NULL → filter drops incomplete windows.
- Missing final ORDER BY on the first version (passed by luck).
- Names fixed: `moving_avg` held a sum; `avg` is a function name.
- After GROUP BY, visited_on is unique → no tie-breaker needed.
- Frame was shown mid-problem (not used). The tool I didn't know was
  **a window frame `ROWS BETWEEN 6 PRECEDING AND CURRENT ROW`**, and it's for
  **moving sums/averages over the last N rows**. → Frame version re-solve Tue.
- LAG and ROWS frames count rows, not days. Missing days → use a calendar join or
  MySQL `RANGE BETWEEN INTERVAL 6 DAY PRECEDING AND CURRENT ROW`.

## #601 Human Traffic of Stadium (MySQL, Hard)
```sql
-- Input grain: one row = one stadium day (id, visit_date, people)
-- Output grain: one row = one Stadium row inside a run of 3+ consecutive ids with people >= 100
-- Window needed? yes, because id - ROW_NUMBER labels each island, COUNT OVER sizes it
-- Keep a row when: its island has 3+ rows
WITH busy_days AS (
  SELECT id, visit_date, people
  FROM Stadium
  WHERE people >= 100
),
labelled AS (
  SELECT id, visit_date, people,
         id - ROW_NUMBER() OVER (ORDER BY id) AS island_label
  FROM busy_days
),
sized AS (
  SELECT id, visit_date, people,
         COUNT(*) OVER (PARTITION BY island_label) AS island_size
  FROM labelled
)
SELECT id, visit_date, people
FROM sized
WHERE island_size >= 3
ORDER BY visit_date;
```
- Gaps and islands on ids (not dates). Filter first, then label = id − rn.
- No dedupe needed: id is unique (contrast with P3).
- Output = EVERY row in the island (not one per streak like P3) → `COUNT(*) OVER (PARTITION BY label)`.
- `COUNT(*) OVER (PARTITION BY x)` = island size on every row.
  Adding `ORDER BY` inside OVER turns it into a running count (1, 2, 3).
- MySQL: ROW_NUMBER returns BIGINT UNSIGNED → negative `id - rn` errors
  ("out of range"). Safe here (rn ≤ id). Portable: `CAST(id AS SIGNED) - rn`.
