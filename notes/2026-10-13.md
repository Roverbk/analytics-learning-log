## Learned
- GROUP BY rule: every SELECT column is a group key or inside an aggregate.
  Group key test: "can I calculate it from one row alone?"
- Output grain line = my GROUP BY keys. Write "one row = one ___".
- Ties: LAG/ROW_NUMBER on tied ORDER BY values = arbitrary result.
  Fix: ORDER BY main_key, tie_breaker (tie-breaker LAST).
- SUM() OVER (ORDER BY x) defaults to RANGE: rows tied on x get the same
  running total. Per-row totals need a tie-breaker. (ROWS alone doesn't fix it.)
- ORDER BY inside OVER() decides values; final ORDER BY decides print order.
  ORDER BY in a CTE does nothing, unless paired with LIMIT.
- LIMIT = N from the whole result. N per group = window + PARTITION BY.
- The tool I didn't know was LAG(col, 2) (the offset), and it's for looking
  more than one row back.

## Dialect notes
- DATE_TRUNC(d, MONTH) (BQ) = DATE_FORMAT(d, '%Y-%m-01') (MySQL, string).
- DATE_DIFF(a, b, DAY) (BQ) = DATEDIFF(a, b) (MySQL).
- SAFE_DIVIDE (BQ only) -> portable: a / NULLIF(b, 0).
- QUALIFY: BQ only. CTE + WHERE works everywhere.
- MySQL comments need a space after "--".
- GROUP BY alias: OK in BQ/MySQL/Postgres, fails in SQL Server.
- Last row: LIMIT 1 (MySQL/BQ/Postgres), TOP 1 (SQL Server).
- 7-day calendar window: MySQL RANGE INTERVAL 6 DAY PRECEDING;
  BQ needs UNIX_DATE(date) RANGE 6 PRECEDING.
- COALESCE is portable; IFNULL is MySQL/BQ only.

-- Input grain: one row = one transaction
-- Output grain: one row = one merchant in one month (top 3 per month only)
-- Window needed? yes, rank within each month; LIMIT would cut the whole result
WITH monthly_spend AS (
  SELECT DATE_TRUNC(txn_date, MONTH) AS month, merchant_id, SUM(amount) AS total_spend
  FROM transactions
  GROUP BY month, merchant_id
),
ranked AS (
  SELECT month, merchant_id, total_spend,
         DENSE_RANK() OVER (PARTITION BY month ORDER BY total_spend DESC) AS rnk
  FROM monthly_spend
)
SELECT * FROM ranked WHERE rnk <= 3 ORDER BY month, rnk;
