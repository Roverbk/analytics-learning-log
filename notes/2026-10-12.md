```sql
-- Output grain: one row = one card with a 3+ day streak
-- Input grain: one row = one transaction
-- Window needed? yes, because days must be numbered in date order per card
WITH dedupe AS (
  SELECT DISTINCT card_id, txn_date FROM transactions
),
numbered AS (
  SELECT card_id, txn_date,
         ROW_NUMBER() OVER (PARTITION BY card_id ORDER BY txn_date) AS rnk
  FROM dedupe
),
islands AS (
  SELECT card_id, txn_date, txn_date - rnk AS island_id FROM numbered
)
SELECT DISTINCT card_id
FROM islands
GROUP BY card_id, island_id
HAVING COUNT(*) >= 3;
```

## P2: Monthly spend drop > 20% — COUNTS

```sql
-- Output grain: one row = one card-month where spend dropped more than 20%
-- Input grain: one row = one transaction
-- Window needed? yes, because LAG gets the previous month per card
WITH monthly AS (
  SELECT card_id, DATE_TRUNC(txn_date, MONTH) AS month,
         SUM(amount) AS total_spend
  FROM transactions
  GROUP BY card_id, month
),
prevmonth AS (
  SELECT card_id, month, total_spend,
         LAG(total_spend) OVER (PARTITION BY card_id ORDER BY month) AS prev_spend,
         LAG(month)       OVER (PARTITION BY card_id ORDER BY month) AS prev_month
  FROM monthly
),
dropped AS (
  SELECT *,
         ROUND(SAFE_DIVIDE(total_spend - prev_spend, prev_spend) * 100, 1) AS pct_change
  FROM prevmonth
)
SELECT card_id, prev_month, prev_spend,
       month AS curr_month, total_spend AS curr_spend, pct_change
FROM dropped
WHERE pct_change < -20;
```
Result: C1, 2026-01-01, 500, 2026-02-01, 200, -60.0

Wins: denominator right first try (wrong twice before). Sign right.
Fixes from review:
- First version used (prev - curr)/prev -> positive for a drop.
  Spec convention: pct_change = (new - old)/old, drop is negative.
- SAFE_DIVIDE(top, bottom) takes TWO arguments. I wrote
  SAFE_DIVIDE((a - b) / c) -> error "found 1 argument".
- ROUND to 1 decimal, not 2. Match spec column names and order.
- Read error messages slowly: they name the function, what it
  expected, and what it got.
DATE_TRUNC(date, MONTH) -> first day of the month, still a DATE.
Known limitation: no row for a month with zero spend -> 100% drops
missed. Calendar fix on Sunday.

## P4: Longest streak per card — HEAVY HINTS

```sql
-- Output grain: one row = one card, showing its longest streak
-- Input grain: one row = one transaction
-- Window needed? yes, two: ROW_NUMBER to number days (streak label),
--   ROW_NUMBER to rank streaks per card
WITH dedupe AS (
  SELECT DISTINCT card_id, txn_date FROM transactions
),
numbered AS (
  SELECT card_id, txn_date,
         ROW_NUMBER() OVER (PARTITION BY card_id ORDER BY txn_date) AS rnk
  FROM dedupe
),
islands AS (
  SELECT card_id, txn_date, txn_date - rnk AS island_id FROM numbered
),
streaks AS (
  SELECT card_id,
         MIN(txn_date) AS streak_start,
         MAX(txn_date) AS streak_end,
         COUNT(*)      AS streak_length
  FROM islands
  GROUP BY card_id, island_id
),
ranked AS (
  SELECT *,
         ROW_NUMBER() OVER (PARTITION BY card_id
                            ORDER BY streak_length DESC, streak_start) AS rn
  FROM streaks
)
SELECT card_id, streak_length, streak_start, streak_end
FROM ranked
WHERE rn = 1;
```
Result: C1 3 (Jan 3–5), C2 2 (Feb 7–8), C3 2 (Feb 14–15), C4 1 (Feb 20)

Key idea: two grains. Days -> streaks (GROUP BY), then streaks ->
best streak per card (window + filter).

Bugs:
- Tried to go straight to one row per card -> skipped the streak label.
- Named a column "islands" inside a CTE called "islands" -> GROUP BY
  read it as the whole table row (STRUCT error). Never reuse names.
- Used streak_end - streak_start in the same SELECT -> can't reference
  an alias where it's created. (Also off by one: needs + 1.)
- COUNT(*) = streak length, but ONLY because I deduped first.
- LIMIT 1 again -> cuts the whole result, not per card (on my list!).
- Forgot the tie-breaker -> non-deterministic if two streaks tie.
- Can't put a window function in WHERE -> rank in one CTE, filter in the next.

Why ROW_NUMBER here: always exactly one rn = 1 per card. RANK and
DENSE_RANK give tied streaks both rank 1 -> card appears twice.

## Summarize vs pick (the big lesson today)
- Summarize a group (total, count, earliest) -> GROUP BY + aggregates
- Pick a row from a group (top 1, longest, latest) -> window + filter
- GROUP BY card_id with MAX/MIN on each column mixes values from
  different rows: C1 -> 3, Jan 3, Feb 2 (not a real streak).
- GROUP BY alternative: find MAX per card, then join back to get the
  row. Works, but needs a join and returns duplicates on ties.

## Tools I didn't know
- DATE_TRUNC: groups dates by month
- SAFE_DIVIDE: two arguments, returns NULL instead of a divide-by-zero error
- Window functions run before DISTINCT, and you can't use them in WHERE
