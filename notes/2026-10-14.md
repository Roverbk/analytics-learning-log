picks from a different streak row. Need ROW_NUMBER to keep one whole row.

```sql
-- Input grain: one row = one transaction
-- Output grain: one row = card_id (every card appears once)
-- Window needed? yes: a running number per card to build the island label,
--   and a ranking per card to pick the longest streak
-- Keep a row when: it is the card's longest streak (earliest if tied)
WITH transactions AS (
  -- setup data: see notes/2026-10-12.md
),
dedupe AS (
  SELECT DISTINCT card_id, txn_date FROM transactions
),
ranked AS (
  SELECT card_id, txn_date,
         DENSE_RANK() OVER (PARTITION BY card_id ORDER BY txn_date) AS rnk
  FROM dedupe
),
islands AS (
  SELECT card_id, txn_date,
         DATE_SUB(txn_date, INTERVAL rnk DAY) AS island
  FROM ranked
),
streak AS (
  SELECT card_id,
         COUNT(*)      AS streak_length,
         MIN(txn_date) AS streak_start,
         MAX(txn_date) AS streak_end
  FROM islands
  GROUP BY card_id, island
),
-- not GROUP BY card_id: MAX/MIN would mix columns from different streaks
ranked_length AS (
  SELECT card_id, streak_length, streak_start, streak_end,
         ROW_NUMBER() OVER (PARTITION BY card_id
                            ORDER BY streak_length DESC, streak_start) AS rnk2
  FROM streak
)
SELECT card_id, streak_length, streak_start, streak_end
FROM ranked_length
WHERE rnk2 = 1;
```

## #185 Department Top Three Salaries (LeetCode, Hard) — COUNTS
"Top three unique salaries" = distinct values -> DENSE_RANK.
No tie-breaker needed: with DENSE_RANK <= 3, ties are all kept,
so the result is reproducible.
```sql
-- Input grain: one row = one employee
-- Output grain: one row = department + employee
-- Window needed? yes: rank salaries within each department
-- Keep a row when: salary is among the department's top 3 distinct salaries
WITH ranked AS (
  SELECT name, salary, departmentId,
         DENSE_RANK() OVER (PARTITION BY departmentId ORDER BY salary DESC) AS rnk
  FROM Employee
),
top3 AS (
  SELECT name, salary, departmentId FROM ranked WHERE rnk <= 3
)
SELECT d.name AS Department, e.name AS Employee, e.salary AS Salary
FROM top3 e
INNER JOIN Department d ON e.departmentId = d.id;
```

## DataLemur: User's Third Transaction (Uber) — COUNTS
Exactly one row per user -> ROW_NUMBER.
No transaction ID, so no perfect tie-breaker. Interview line: "if
timestamps tie, 'third' is ambiguous; I'd ask for a transaction ID or
use spend as a stable fallback."
```sql
-- Input grain: one row = one transaction
-- Output grain: one row = user_id
-- Window needed? yes: number each user's transactions in date order
-- Keep a row when: it is the user's 3rd transaction
WITH ranked AS (
  SELECT user_id, spend, transaction_date,
         ROW_NUMBER() OVER (PARTITION BY user_id
                            ORDER BY transaction_date, spend) AS rnk
  FROM transactions
)
SELECT user_id, spend, transaction_date
FROM ranked
WHERE rnk = 3;
```

## DataLemur: Highest-Grossing Items (Amazon) — COUNTS
Two grains: transactions -> product totals (GROUP BY) -> rank per category.
Errors on the way: HAVING after ORDER BY (syntax), year filter in
HAVING ("column does not exist").
```sql
-- Input grain: one row = one purchase (user, product, category, date)
-- Output grain: one row = category + product
-- Window needed? yes: rank products by total spend within each category
-- Keep a row when: product is in its category's top 2 for 2022
WITH spend_per_product AS (
  SELECT category, product, SUM(spend) AS total_spend
  FROM product_spend
  WHERE transaction_date >= '2022-01-01'
    AND transaction_date <  '2023-01-01'
  GROUP BY category, product
),
ranked AS (
  SELECT category, product, total_spend,
         ROW_NUMBER() OVER (PARTITION BY category
                            ORDER BY total_spend DESC, product) AS rnk
  FROM spend_per_product
)
SELECT category, product, total_spend
FROM ranked
WHERE rnk <= 2;
```

## New mistakes
- OVER = window functions. ON = joins.
- WHERE filters ROWS before grouping. HAVING filters GROUPS after, and
  only sees group keys + aggregates.
- Clause order: SELECT, FROM, WHERE, GROUP BY, HAVING, ORDER BY.
- MySQL: date - int turns the date into a number (20260201 - 1 = 20260200).
  Use DATE_SUB(d, INTERVAL n DAY).

## New concepts
- After dedupe, DENSE_RANK = ROW_NUMBER (dates unique per card) and no
  tie-breaker is needed. Say this out loud in interviews.
- Year filter: range (>= '2022-01-01' AND < '2023-01-01') can use an
  index / partition pruning; YEAR(col) can't. Use < next year, not
  <= Dec 31 (timestamps).

## Dialect notes (add)
- DATE_SUB(d, INTERVAL n DAY): MySQL + BQ. MySQL unit is singular (DAY).
  Postgres: d - n * INTERVAL '1 day' (d - n also works: real date math).
- Year: EXTRACT(YEAR FROM d) everywhere; YEAR(d) MySQL only, not BQ.
- TOP is reserved in SQL Server -> don't name a CTE "top".
